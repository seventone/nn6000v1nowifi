【本文作用】

【修改总原则（严格遵守）】
  * 只删不加：能后期 opkg 装的一律不编进固件，只保留系统完整稳定+有线网络畅通
  * 不留 WiFi：所有无线驱动 / 固件 / 接口一律删除
  * 旁路由模式：没有 WAN/WAN6，三网口全桥 LAN，DHCP 关，IPv6 默认关但保留模块
  * 网口重命名：原 WAN→lan1，原 LAN1→lan2，原 LAN2→lan3
  * 自定义 MAC 地址编译进固件（三物理口分别设、br-lan 网桥跟随 lan1）
  * 仅保留两种固件：factory.bin（首次刷机）+ squashfs-sysupgrade.bin（升级）
  * 仅保留 NN6000 V1 无WiFi版一个设备型号，删除其他所有型号

2.2.1 缓存策略（大幅增强，原作者是单 cache，我们拆成两段）
────────────────────────────────────────
原作者（单 cache）：
  - 单一 actions/cache，key=...，同时包含 ccache + dl + staging_dir/*
  - 一旦源码哈希变了，整条 cache 失效，ccache 和 dl 目录也跟着没

我们（拆成两段 cache，命中最大化）：
  Cache1 "Cache CCache & DL"  （[WRT-CORE.yml:119-133]）
    key   = ccache-${WRT_CONFIG}-${WRT_INFO}-${WRT_HASH}-${WRT_DATE}
    restore-keys:
      ccache-${WRT_CONFIG}-${WRT_INFO}-${WRT_HASH}
      ccache-${WRT_CONFIG}-${WRT_INFO}
      ccache-${WRT_CONFIG}                  ← 宽松匹配，尽量复用历史 dl/ccache
    path:   ./wrt/.ccache  ./wrt/dl
    特点：   日期滚动 + 宽松 restore，源码变了也尽量复用最近的 ccache/dl

  Cache2 "Cache Toolchain & Host"  （[WRT-CORE.yml:134-145]）
    key   = toolchain-${WRT_CONFIG}-${WRT_INFO}-${WRT_HASH}   ← 严格绑定源码哈希
    restore-keys: toolchain-${WRT_CONFIG}-${WRT_INFO}
    path:  ./wrt/staging_dir/host*  ./wrt/staging_dir/tool*
    特点：  源码不更新时 toolchain 100% 复用；源码变了才清旧条目

  Update Caches 步骤（[WRT-CORE.yml:146-181]）额外加：
    - ccache -s 打印命中统计（便于观察命中率）
    - WRT_HASH 变化时，gh cache delete 清理"同配置旧 toolchain"，避免占满 10GB 配额
    - 打印 cache hit / miss 提示

  环境变量（[WRT-CORE.yml:61-64]）：
    CCACHE_MAXSIZE=10G
    CCACHE_COMPRESS=true
    CCACHE_COMPRESSLEVEL=6
    （原作者默认或更小；我们放大到 10G + 压缩，二次编译速度提升最明显）

2.2.3 Initialization Environment 容错（[WRT-CORE.yml:84-91] 时区）
────────────────────────────────────────
原作者：sudo -E timedatectl set-timezone "Asia/Shanghai"
        GitHub Actions runner 偶尔会报 Access denied（PolicyKit 没就绪）→ 整个工作流 exit 1。

     如果以后再撞到 Access denied，再切成纯文件写法：
       sudo ln -sf /usr/share/zoneinfo/Asia/Shanghai /etc/localtime
       echo "Asia/Shanghai" | sudo tee /etc/timezone
     （本留档写出来，下次不用再查）

2.6 Scripts/Settings.sh     （定制核心，改动最大的脚本）

定位：WRT-CORE.yml 的 Custom Settings 步骤 `$GITHUB_WORKSPACE/Scripts/Settings.sh` 在
      ImmortalWrt 源码目录内执行，负责在 make defconfig 之前：

2.6.1 .config 追加写入（[Settings.sh:67-74] 基础配置注入）
────────────────────────────────────────

2.6.2 ATHD Makefile 去 N 结尾（[Settings.sh:77-98]）
────────────────────────────────────────
作用：高通 NSS 驱动在 ImmortalWrt 里通常有两种 package 名，xxx-N 结尾是"带 NSS 功能"版，
     我们要确保 NSS 相关都选 N 版、或至少 Makefile 不因为 N 后缀和默认冲突。
     这一段原作者就有，我们**保持原样**不改动；
     唯一加的保险：每个 sed 前先 find，有文件才 sed，避免路径不存在时报错。

────────────────────────────────────────
2.6.3 board.d/02_network patch（[Settings.sh:106-140] 网口 LAN 组改写）
────────────────────────────────────────
作用：board.d/02_network 决定 netifd 启动时 "LAN 组有哪些 label / WAN 组有哪些 label"。

原作者对 link,nn6000-v1 分支默认：
  link,nn6000-v1)
    ucidef_set_interfaces_lan_wan "lan1 lan2" "wan"
    ;;
（2 LAN + 1 WAN，WAN 做普通路由用）

我们 patch 成（核心 1 行）：
  sed -i '/link,nn6000-v1)/,/;;/ {
      s/.*ucidef_set_interfaces_lan_wan.*/\tucidef_set_interfaces_lan_wan "lan1 lan2 lan3" ""/
  }' target/linux/qualcommax/ipq60xx/base-files/etc/board.d/02_network

要点：
  * 范围锁死：/link,nn6000-v1)/,/;;/ 只改 nn6000-v1 这个 case，
    绝对不会误伤 dptech-ap3000-2c / 8devices-mango-dvk / glinet-gl-axt1800
    这些和它共用同一条配置的其他设备（方案 1 全局 s|||g 没加范围就踩了坑）
  * 用 .*整行替换.*，不是 \s+ 精确匹配参数（BRE \s+ 不支持、导致替换没生效）
  * 结果：LAN 组 = "lan1 lan2 lan3"，WAN 组 = ""，3 个口全进 LAN

────────────────────────────────────────
2.6.4 DTS patch：网口 label 重命名（[Settings.sh:142-164]）
────────────────────────────────────────
目标：原作者固件 label 顺序是 "wan / lan1 / lan2"（机箱丝印或 LuCI 显示）。
      用户要求：三个口统一 LAN，而且按
          原 WAN  口  →  lan1
          原 LAN1 口  →  lan2
          原 LAN2 口  →  lan3
      显示。

执行：在 nn6000-v1 的 DTS（设备树）文件中用 sed 改 label：
  * 顺序要"倒着改"，先改最后一个不会被后面覆盖：
      LAN2 label  →  lan3
      LAN1 label  →  lan2
      WAN  label  →  lan1
  * 每个 sed 前面先 find + 非空判断，避免 DTS 文件名 / 路径和我们预期不一致时出错。

DTS patch 完成后，配合 2.6.3 board.d 的 LAN 组 "lan1 lan2 lan3"，
开机 LuCI 显示就是 lan1 / lan2 / lan3 三个口，全都在 br-lan 里，不分 WAN。

2.6.5 写 /etc/uci-defaults/99-nn6000v1nowifi（首次开机初始化脚本）
────────────────────────────────────────
这是 Settings.sh 最大一块（Heredoc，UCI_EOF 包起来），共 8 段：

  2.6.5.1 删除 WAN / WAN6 接口（[UCI_EOF 第 183-188 行]）
    uci delete network.wan
    uci delete network.wan6
    uci delete network.wan_dev
    uci delete network.wan6_dev
    （彻底删除，不是 disable；重启也不会重新出现）

  2.6.5.2 自定义 MAC 地址（[UCI_EOF 第 191-290 行]）★ 最关键的一块
    用户指定：
      lan1 = f8:5e:3c:4c:50:7a
      lan2 = f8:5e:3c:4c:50:7b
      lan3 = f8:5e:3c:4c:50:7c
      br-lan = 跟随 lan1 = f8:5e:3c:4c:50:7a
    实现：
      (a) 先清理可能遗留的"命名 device section"（network.lan1 / network.lan2 /
          network.lan3 / network.br_lan）→ 避免和 board.d 匿名 section 冲突
          （上一版写 `uci set network.br_lan='device'` 导致 LuCI 显示两个 br-lan）
      (b) 用 while 循环遍历 network.@device[i]，把重复出现的 name=lan1/lan2/lan3
          匿名 section 删掉，留空；把第二个及以后的 name=br-lan 匿名 section 删掉
          （只保留第一个 board.d 生成的）
      (c) 用 `uci add network device` 分别新建 3 个匿名 device section，
          每个写 name='lan1/lan2/lan3' 和 macaddr='...'
      (d) 再次 while 循环找到 name='br-lan' 那个匿名 section：
          set macaddr（不新建第二个！），如果缺 ports 再 add_list 补 lan1/lan2/lan3
      (e) 最后 `uci set network.lan.device='br-lan'` 绑定逻辑 LAN 接口到网桥
      (f) 启动时立即生效：4 个 `if [ -d /sys/class/net/X ]` 块，
          `ip link set dev X address MAC` 立刻把内核接口刷成新 MAC，
          避免网口 bring up 时把原厂 MAC 告诉交换机 ARP。

    合法性：
      * 第 1 字节 0xf8 = 1111_1000，最低位 =0，合法单播
      * 前 5 字节 f8:5e:3c:4c:50 与原厂 OUI 对齐
      * 三个口最后 1 字节 7a/7b/7c，与原厂 79/7a/7b 错开不冲突

  2.6.5.3 LAN 静态 IP / 掩码 / 网关 / DNS（[UCI_EOF 第 292 行起]）
    PLACEHOLDER_LAN_IP / _MASK / _GW / _DNS1 / _DNS2
    → Heredoc 写完后，用 5 条 sed 把占位符换成脚本开头的常量（[Settings.sh:380-384]）
    实际写入：
      network.lan.proto=static
      network.lan.ipaddr=10.0.0.30
      network.lan.netmask=255.255.255.0
      network.lan.gateway=10.0.0.100
      network.lan.dns="10.0.0.5 223.5.5.5"
      network.lan.delegate=0          ← 关掉 IPv6 前缀下发
      delete ip6assign / ip6hint

  2.6.5.4 关闭 DHCP（旁路由模式必须）
    dhcp.lan.ignore='1'          ← 不响应 DHCP 请求
    dhcp.lan.dhcpv6='disabled'
    dhcp.lan.ra='disabled'
    odhcpd maindhcp=0 + /etc/init.d/odhcpd disable
    （DHCP 由主路由提供，避免和主路由 DHCP 冲突）

  2.6.5.5 IPv6 默认关闭（内核模块保留，用户需要再手动开）
    network.globals.ula_prefix 清空
    /proc/sys/net/ipv6/conf/{all,default}/disable_ipv6 =1
    /etc/sysctl.conf 两行 disable_ipv6
    （用户需要 IPv6 时，把 disable_ipv6 改成 0 就行）

  2.6.5.6 防火墙：删除 WAN zone，仅保留 LAN zone
    while uci -q delete firewall.@zone[0] 循环清空所有 zone
    add 一个新 zone：name=lan / network=lan / input=ACCEPT / output=ACCEPT /
                    forward=ACCEPT / masq=0 / mtu_fix=0
    forwarding 规则清空
    （旁路由没有 WAN↔LAN 转发需求）

  2.6.5.7 写死 /etc/resolv.conf，避免被别的脚本覆盖回默认 DNS

  2.6.5.8 清理虚拟模板接口（双保险清理）★ 新增
    for _dev in dummy0 erspan0 gre0 gretap0 ip6gre0 ip6tnl0 sit0:
      存在则 ip link set down + ip link delete
    再 rmmod dummy / gre / ip_gre / gretap / ip6gre / ip6_tunnel /
            sit / ipip / erspan
    （即便 GENERAL.txt =n 拦不住的 built-in，这里也彻底从运行时删掉，LuCI 设备页
      只会显示 br-lan + lan1 + lan2 + lan3 + lo，清爽）

Heredoc 写完之后：
  * 5 条 sed 替换 5 个 PLACEHOLDER_* → 真正的 IP/GW/DNS
  * 打印两行 echo 日志，方便 make 阶段观察注入成功没

坑 1：Actions 看不到 NN6000V1NOWIFI 工作流
    → 原因：扩展名是大写 .YML，GitHub 只认 .yml/.yaml
    → 修复：改名成小写 .yml（已修）

坑 2：编译出来 LuCI 英文
    → 原因：漏写 CONFIG_LUCI_LANG_zh_Hans=y + CONFIG_PACKAGE_luci=y
    → 修复：Settings.sh .config 注入两行（已修）

坑 3：启动后 br-lan 只有 lan1+lan2，缺 lan3（进不了桥）
    → 原因：board.d sed 用 BRE 正则 \s\+，BRE 不支持 → 替换完全不匹配
    → 修复：改成 /link,nn6000-v1)/,/;;/ 范围锁 + 整行 .* 替换（已修）

坑 4：LuCI 设备页显示两个 br-lan
    → 原因：`uci set network.br_lan='device'` 新建了一个命名 section
          和 board.d 生成的匿名 device（name=br-lan）同时存在冲突
    → 修复：一律用匿名 section（uci add network device）+ name='...'
          找现有 name=br-lan 的 section 改 macaddr，永不新建第二个（已修）

坑 5：首次编译撞到 "Failed to set time zone: Access denied"
    → 原因：timedatectl set-timezone 需要 PolicyKit 就绪，GitHub Actions runner
          偶尔环境没 ready
    → 修复：多 Run workflow 一次；真撞了多次再切成 ln -sf /etc/localtime 纯文件方式（已记录）

坑 6：Auto-Clean 每天清空所有 Release/Tag
    → 原因：原作者 Auto-Clean.yml 每天 5 点跑 ophub/delete-releases-workflows
          releases_keep_latest=0 / workflows_keep_day=0
    → 修复：整个 Auto-Clean.yml 删除（已修）

坑 7：Cache-Clean 每周把 ccache/dl/toolchain 全清，下次编译又从零开始
    → 原因：原作者 schedule 每周日 20:00 UTC 跑 gh cache delete --all
    → 修复：schedule 注释掉，依赖 GitHub 10GB LRU 自动淘汰（已修）

坑 8：dummy0/erspan0/gre0/... 一堆虚拟模板口看着乱
    → 原因：kmod-dummy/kmod-gre/erspan 等被编进固件，加载时自动建 0 号模板
    → 修复：GENERAL.txt 显式设 =n；uci-defaults 末尾再加双保险清理循环（已修）
